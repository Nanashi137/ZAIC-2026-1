# Phase 04.5 — Competition compliance and runtime hardening

Status: COMPLETE on 2026-11-01. Offline local-LLM migration remains Phase 05.

## Scope and dependencies

This phase hardens the existing Phase 04 runtime without changing prompts, tool selection, submission shape, or the
official SDK. It depends on the Phase 03 local ASR and Phase 04 batch/session isolation. It does not provide the final
offline LLM or private Docker entrypoint.

## Subtasks

- Enforce a monotonic per-sample deadline, defaulting to 28 seconds in competition mode, across ASR, history, model
  requests/retries, agent steps, tool calls, and SDK output capture.
- Centralize seed 42 and deterministic Python/NumPy/PyTorch/CUDA setup; explicitly request greedy ASR generation.
- Formalize competition mode: reject non-local endpoints, disable post-batch official validation, and retain exactly
  one inference ToolEnv per sample.
- Remove environment-path probing from repository diagnostics and statically guard inference source against direct
  environment-file access or `get_state()` calls.
- Supply an outer one-process-per-sample watchdog for synchronous CUDA/backends that cannot be cancelled safely from
  a Python thread.

## Acceptance

- Timeout is reported as `sample_timeout`, never success; failed samples do not produce fabricated submission rows.
- Model request timeout and retry/rate-limit waits cannot exceed the remaining sample budget.
- Fixed-seed mock runs repeat and available numerical runtimes receive deterministic configuration.
- Competition mode defaults to 28 seconds, creates one ToolEnv, and never invokes the validator that creates another.
- Successful output still uses exact `get_tool_calls()` and `get_state_hash()` values and the unchanged three-field
  JSONL schema.
- Development mode, separate official validation, existing CLI flags, and prior tests remain functional.
- Blocking `qwen-asr` CUDA execution is explicitly documented as cooperatively non-interruptible; the outer watchdog
  demonstrably terminates its child process. Phase 05 must wire this boundary into final packaging.

## Known boundary

The official `qwen-asr==0.0.6` `transcribe()` signature has no timeout/cancellation argument and calls synchronous
Transformers generation internally. Deadline checks detect overrun after return but cannot preempt its CUDA kernel.
Only terminating the dedicated child process is a hard stop. A multi-sample process must not be presented as having
a hard per-sample CUDA timeout; the Phase 05 scored entrypoint must use one watchdog child per sample or an equivalent
organizer-verified worker isolation design.
